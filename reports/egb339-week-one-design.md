# Design System: EGB339 Week 1 pilot

## Overview

Scope: `/egb339/uker/uke-1` only. Visitor mode: Read. Approved by the user on 2026-09-11. No rollout to weeks 2–8, no changes to existing lab mathematics or authored assessment answers.

**Creative North Star: "Codecademy course navigation + visual engineering textbook + interactive robotics notebook"**

Study clarity drives the implementation: an expanded syllabus, chronological article, labeled diagrams, worked examples, and controls next to their mathematical consequences. The pilot inherits EGB339's reading type and restrained control shapes. Color identifies frames or explicit status; spacing and rules organize the lesson.

**Key Characteristics:**

- Persistent course navigation and native document scrolling.
- Readable prose interleaved with wider engineering figures.
- Labeled A/B identities, semantic feedback, and existing completion keys.
- Flat surfaces, small control corners, and immediate state changes.

### Direction contract

THESIS: One chronological study page connects the physical robot, its mathematical description, Python and assessment preparation. Refuse both a link-only reading index and decorative dashboard cards.

OWN-WORLD: Inherit EGB339's article typography and small control radii. Add semantic status colors and stable blue A / purple B identities, with labels and line styles. No glows, gradients, decorative icons or entrance animations.

STORY: Identify the week's subject, follow inline explanation and diagrams, work a small example, try a control, check the existing answer and mark the existing learning item complete.

FIRST VIEWPORT: Persistent compact syllabus at left; breadcrumb, Week 1 title and short introduction at right; a real Robotics Toolbox robot-model image connects to the first technical explanation. Wide figures alternate with a readable article measure.

FORM: User-pinned course navigation + engineering article, explicitly approved rather than generated by a concept tournament. Two interactions: same-point versus moving-object frame explorer; QUT Q15 row-by-column matrix explorer. Native document scrolling with anchor navigation and reduced-motion support.

FINISH: the build requires a finish review and verdict, these EGB339-scoped design reports (`reports/egb339-week-one-design.md` and `reports/egb339-week-one-design.json`), and provenance for every shipping raster. The parent QA report records verification results; this document records implemented design and makes no QA verdict.

Documentation boundary: record this pilot's design and QA in EGB339-specific reports, not a root-wide design system. The user's precise approved scope takes precedence over global Impeccable initialization/world-selection artifacts. No new site-wide workflow preferences.

### Evidence and source boundaries

- QUT `raw/week1-kinematics/EGB339 - 2026 - Lecture Week 1.pdf`: pages 11, 13, 14 for camera/manipulator/frames; page 53 says tutorials and practicals begin in week 2.
- Corke, *Robotics, Vision and Control*, third (Python) edition, 2023: chapter 1; sections 2.1.1–2.1.2, figures 2.1 and 2.4–2.6. Both existing Markdown and original PDF inspected; PDF resolves damaged Markdown notation.
- QUT `Warmup to Gradescope.pdf`, pages 1–6: existing 15 walkthroughs remain the single source. Preserve missing-start-file warnings and Q15's corrected product `[19,22;43,50]`.
- Robotics Toolbox: repository and ecosystem AGENTS.md followed; `examples/teach.py`, `models/ETS/Planar2.py`, `docs/source/intro.rst`, and SpatialMath used as references. Planar2's implementation, not its stale branched-robot docstring, is the geometry reference.
- PDF photographs have no verified republication licence here. Do not ship them. Use original geometric diagrams plus `docs/figs/swift.png`, an existing MIT-licensed RTB documentation image, with the repository licence and explicit provenance. The Panda is a model illustration, not the course's Dobot.

### Preserved implementation decisions

- Taste dials: variance 4, motion 2, density 5. Education-specific overrides: meaningful matrices/coordinate grids, existing completion glyphs and semantic multi-object colors are functional, not decoration.
- Diagram Design: system architecture with a feedback path, schematic kinematic chain, and exact coordinate geometry. Use the approved EGB339 colors and fonts rather than the skill's default orange/serif skin. Inline React SVG replaces standalone HTML because these diagrams are part of the lesson.
- Desktop sidebar is independently scrollable, with no collapsed week groups. Only the Week 1 route uses the new sidebar initially.
- Reuse existing page keys. New introductory sections track reading position, not invented completion or completion of a later week's topic.
- Preserve old routes and `#leksjoner`, `#ukeinnhold`, `#oppgaver`, `#vurderinger`; introduce stable named sections and `#solution-q1`…`#solution-q15` on the pilot.
- QA: 1440×1000 and 1280×900, both themes; initial screenshot review, one batched correction/confirmation, independent finish review; anchors, keyboard, progress success/failure, console/network and validators.

Implementation evidence: `src/app/egb339/week-one.css`, inherited `pilot.css`, and `src/components/egb339/week-one/WeekOneNavigation.tsx`, `WeekOneExplorers.tsx`, `WeekOnePage.tsx`, and `WeekOneDisclosure.tsx`. ## Colors

The light/dark pairs in frontmatter are the actual CSS values; `dark-` means the corresponding `.dark` override. No additional palette or tonal ramps are introduced.

### Primary

`week-info` supplies links, focus outlines, current reading location, and frame A; CSS aliases `week-frame-a` to it. Selected controls and the active sidebar row use `week-info-tint`. Frame A is an object identity, not a success state.

### Secondary

`week-frame-b` identifies frame B and matrix B; `week-b-tint` marks the selected B column. B's sliders use the same accent. Text labels and solid/dashed axes carry meaning alongside color.

### Semantic status

Success, error, and warning each pair foreground with its own tint. Completion uses success; the conditional check says “Riktig” or “Ikke riktig”; source limitations and Q15's correction use warning. Color never supplies the message alone.

### Neutral

Paper, ink, muted, line, and hover are inherited EGB339 roles. They define the reading surface, body text, secondary text, separators, and hovered controls. The shared site header retains its inherited green accent outside this route's local blue accent.

## Typography

Use the inherited body family for the article, headings, controls, and SVG labels; no new display font is introduced. The frontmatter captures the actual headline, section, subheading, body, caption, navigation, button, and matrix roles.

The introduction uses a larger muted summary (19px), an opening question heading (23px), and compact prose (16px, line-height 1.65). Regular explanatory prose remains at the body role; explorer copy uses 15px. SVG labels use 16px with secondary labels at 14px. Numerical outputs use tabular numerals; KaTeX retains its mathematical fonts at 1.08em. Inline code scales to .88em and keeps the existing monospace renderer.

Below 768px, inherited article text becomes 16px. This is a responsive implementation fact; the approved finish-review viewports remain desktop.

## Layout

The centered main container has a maximum width of 1440px and padding of 28px 40px 64px. At the approved 1440px viewport, the course column is 260px with a 40px gap; at 1280px it is 244px with a 32px gap. The article occupies the remaining width. Prose caps at 740px; selected figures and explanation pairs cap at 860px.

The sidebar sticks 92px from the top and occupies `calc(100dvh - 116px)`. Its week list flexes into the available height, scrolls independently, reserves a stable scrollbar gutter, and is keyboard focusable. Course identity, progress, references, and the existing tutor action occupy reserved slots. All week groups stay expanded.

The local jump navigation sticks at 64px with layer 20, below the shared header at layer 50. It wraps as needed. Anchor targets use a 160px scroll margin; reading location is measured at a 164px line. The opening uses 1.15:1 columns with a 32px gap; the frame explorer uses 1.2:1 columns with a 36px column gap and a 24px row gap. Major sections are separated by 64px.

Responsive rules: at or below 1300px, the sidebar/gap shrink and opening/explorer gaps become 24px; at or below 1279px, main horizontal padding becomes 24px. At or below 1050px, opening/explorer columns stack and jump navigation becomes static. At or below 767px, the course grid stacks, the sidebar becomes static with a 280px maximum height, paired explanations stack, and section spacing becomes 44px. The existing floating tutor remains the smaller-screen action; its reserved sidebar instance is shown from 768px.

## Elevation & Depth

Lesson sections, explorers, and exercises use flat paper, whitespace, and thin separators. Selected and semantic states use tonal fills. No card grid, lesson shadows, gradients, glow, or entrance animation is part of this pilot. The inherited tutor trigger's outer pulse, shadow, gradient, and scale effect are suppressed by the pilot styles.

Theme changes switch paper and ink immediately. Local links, buttons, and navigation have no transition. Native scrolling is smooth by default and becomes automatic under reduced motion; direct solution reveals scroll immediately after the answer opens. Motion, breakpoint, and focus extensions are recorded in the adjacent JSON sidecar.

## Shapes

Controls use the control radius; sidebar items, notices, matrix cells, and the robot image use the compact radius. Sections and explorers use straight horizontal rules instead of enclosed panels. Standard rules are 1px; current jump links use a 2px underline.

Matrix brackets have square corners, 2px strokes, and 7px bracket ends. Their two columns are 48px wide with 4px gaps; result buttons have a minimum height of 42px. Diagram identity is geometric: labeled frames and axes, dashed y-axes, and a diamond for point P.

## Components

**Buttons and inputs.** The Week 1 button has a 38px minimum height, a neutral border, and a blue label. Hover changes fill and border; `aria-pressed` adds the selected tint. Completion reuses the existing control with 8px 16px padding and blue border; the Week 1 font reset makes it inherit article typography. Saving and unavailable states disable it. Range inputs are native, explicitly labeled, 28px high, and paired with tabular numeric outputs.

**Navigation and links.** The active sidebar location has a tinted row and semibold label; the jump link has an underline and `aria-current="location"`. Native hash links preserve the opaque current route history state; after a client return mounts the page, its URL fragment target is scrolled into view immediately. Prose, preparation-list, caption, source, and question-index links are underlined. Focus is a 2px blue outline with 4px offset; the scrollable week list sets offset to zero so the outline fits its container.

**Frame explorer.** Mode controls distinguish a point attached to B from a fixed physical point. Switching mode preserves the current physical point; A/B coordinate controls change only its description. The drawing uses equal axis scales (44 SVG units per length unit), starts with a 520×480 viewBox, and expands around actual geometry when needed. The grid interval is two length units. Reset restores the worked example; matrix output follows the controls without decorative animation.

**Matrix explorer.** A's selected row is blue and B's selected column purple. Four labeled result buttons expose their pressed state. The calculation is announced politely; next-step cycles through the four elements. The QUT and identity examples, reset, and optional `@` versus `*` comparison reuse the same existing mathematical data.

**Feedback and answers.** Notices explain their warning in text. The conditional check uses labeled success/error messages with `role="status"`. Each existing answer uses a button with `aria-expanded`/`aria-controls`, a stable direct link, and a hidden region that opens on its hash. Print styles reveal answers and hide lesson actions. Completion, loading failures, and write failures retain existing API keys and explicit status/error text.

## Do's and Don'ts

### Do

- Do keep this design confined to the Week 1 pilot and preserve existing content, routes, completion keys, and source qualifications.
- Do keep A/B labels and line styles alongside their stable colors; use explicit words for success, error, and warning.
- Do put explanations, controls, results, and worked calculations next to the figure they describe.
- Do preserve underlined reading links, visible keyboard focus, native document navigation, and reduced-motion scrolling.

### Don't

- Don't roll this pilot into weeks 2–8 or create root-level product, design, or workflow artifacts without an expanded task.
- Don't add decorative dashboard cards, glows, gradients, icons, or entrance animations to the lesson.
- Don't turn reading position into completion, or hide a missing source behind an apparently exact answer.
- Don't ship unlicensed course photographs or present the Panda model as the course's Dobot.
